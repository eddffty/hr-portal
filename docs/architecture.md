# Архитектура и правила HR-портала

## Слои

`Controller → Service → Repository`.

Контроллеры принимают запросы и проверяют роль через `SessionService`. DTO ограничивают размеры комментариев, число смен и обязательные поля. Сервисы проверяют права на конкретные записи, доступность, пересечения и переходы состояний. Репозитории отвечают за хранение; текущая реализация — память процесса.

`PortalQueryService` собирает отдельные представления для текущего пользователя. На клиент не передаются хеши паролей, скрытые отклики посторонних или персональные уведомления других сотрудников.

## Модели

| Сущность | Назначение |
| --- | --- |
| UserProfile / UserAccount | Профиль, роль, соль и хеш пароля |
| Shift | Общая смена с единственным текущим владельцем или свободная смена |
| ExchangeOffer | Общая публикация смены и список отказавшихся кандидатов |
| ExchangeRequest | Отдельная заявка: тип, участники, смены, статус и комментарий |
| Notification | Персональное событие с собственной отметкой прочтения |
| TimeEntry | Фактическое начало и окончание дежурства |
| AuditEvent | Кто и когда изменил назначение, запрос или отметку времени |

Шифрование паролей: PBKDF2-HMAC-SHA256, отдельная случайная соль для каждого аккаунта. После успешного входа создаётся отдельная сессия для вкладки на два часа. Непредсказуемый токен хранится клиентом в sessionStorage, передаётся в Authorization: Bearer; сервер хранит только его SHA-256 и проверяет пользователя и роль на каждом маршруте. Переданный недействительный токен не подменяется общей cookie-сессией. Выход отзывает токен только текущей вкладки. Для совместимости с API-клиентами без заголовка сохранена обычная HTTP-сессия; браузерный интерфейс требует токен вкладки.

## Биржа

Публикация имеет статусы `OPEN`, `RESERVED`, `COMPLETED`, `CANCELLED`.

- Отказ кандидата добавляет только его логин в `declinedBy`; сама публикация остаётся `OPEN`.
- Отклик создаёт отдельный `TRANSFER` со статусом `WAITING_MANAGER`, а публикация становится `RESERVED`.
- Зарезервированная публикация остаётся в «Моих предложениях» владельца. Кандидат видит свой отклик в запросах. Остальным кандидатам она не показывается.
- Одобрение меняет владельца смены и завершает публикацию.
- Отказ руководителя сохраняет владельца, возвращает публикацию в `OPEN` и скрывает её для отказанного кандидата. Остальные пользователи могут откликнуться.
- Инициатор может отменить необработанную заявку. Публикация снова становится открытой.

## Адресный обмен

`SWAP` содержит ровно две смены и конкретного получателя. До согласия коллеги статус — `WAITING_COLLEAGUE`; после согласия — `WAITING_MANAGER`.

При отказе коллеги запрос исчезает из его входящих, но остаётся в истории инициатора. Чужие запросы не затрагиваются.

При одобрении руководителем сначала проверяются обе смены и доступность обоих сотрудников. Только после всех проверок меняются оба владельца. При ошибке назначения сохраняются без изменений.

## Свободные смены

`ASSIGNMENT` содержит выбранные свободные смены. До одобрения они резервируются заявкой. Одновременная заявка другого сотрудника на эти же смены отклоняется сервером. При отказе или отмене резерв освобождается.

## Согласованность

Все изменения расписания, публикаций, заявок и рабочих сессий выполняются под одним `WorkflowLock`. Чтение составного состояния выполняется под тем же замком. Это обеспечивает атомарность операций в одном процессе приложения и предотвращает два одновременных успешных отклика на одну смену.

При переходе к PostgreSQL нужны реальные транзакции, проверка версии/блокировка смен и ограничения уникальности; одного замка Java для нескольких серверов недостаточно.

Перед принятием решения проверяются актуальный статус, текущие владельцы и отсутствие пересечений. Отмена и повторное решение после обработки запрещены.

## Роли

| Действие | Сотрудник | Ответственный | Руководитель |
| --- | --- | --- | --- |
| Смотреть общий календарь и профиль | Да | Да | Да |
| Публиковать и принимать смены, адресный обмен | Да | Нет | Нет |
| Начинать и завершать своё дежурство | Да | Нет | Нет |
| Создавать смены, менять назначения, уведомлять о публикации | Нет | Да | Нет |
| Одобрять/отклонять заявки | Нет | Нет | Да |
| Смотреть фактическое время сотрудников | Только своё | Да | Да |

Для прототипа функции ответственного и руководителя разведены. Они не могут одобрять заявки из обычного аккаунта подменой HTTP-запроса.

## Рабочее время

Начать можно только собственную сегодняшнюю смену без текущих обменов. Одновременно разрешена одна незавершённая рабочая сессия пользователя. Завершать чужую сессию нельзя. Повторный старт/стоп завершённой смены запрещён. Длительность считается сервером по фактическим отметкам; плановая длительность берётся из смены.

| Маршрут | Действие |

| POST /api/login, /api/logout | Вход и выход |
| GET /api/profile, /api/rating | Профиль и тестовый рейтинг |
| GET /api/state?week=YYYY-MM-DD | Календарь и персональные данные |
| POST /api/offers/{shiftId} | Публикация своей смены |
| DELETE /api/offers/{offerId} | Снятие открытой публикации |
| POST /api/exchange/{offerId}/apply | Отклик с резервированием |
| POST /api/exchange/{offerId}/decline | Персональный отказ |
| POST /api/swaps | Адресный обмен двумя сменами |
| POST /api/proposals | Заявка на свободные смены |
| POST /api/requests/{id}/decision | Согласие/отказ получателя обмена |
| POST /api/requests/{id}/cancel | Отмена инициатором |
| GET /api/manager/requests | Очередь и история согласования |
| POST /api/manager/requests/{id} | Решение руководителя |
| POST /api/schedule/shifts | Создание смены ответственным |
| PUT /api/schedule/shifts/{id} | Изменение назначения |
| POST /api/schedule/publish | Уведомление о публикации расписания |
| POST /api/time/start/{shiftId}, /api/time/stop/{entryId} | Отметки времени |
| POST /api/notifications/read | Прочтение своих уведомлений |
