# HR-портал

Java 17 + Spring Boot 3.5.7 + Hibernate (JPA) + PostgreSQL + Flyway + Maven. Интерфейс на HTML/CSS и JavaScript-модулях; его раздаёт Spring Boot. Для запуска приложения Node.js не нужен.

## Запуск

Сначала запустите PostgreSQL (Docker Desktop должен работать):

```powershell
docker compose up -d --wait
```

Если в установленном Docker нет команды `compose`, выполните один раз:

```powershell
docker run --name hrportal-postgres --detach --restart unless-stopped --publish 127.0.0.1:5433:5432 --env POSTGRES_DB=hrportal --env POSTGRES_USER=hrportal --env POSTGRES_PASSWORD=hrportal_local --volume hrportal-data:/var/lib/postgresql/data postgres:17
```

Для последующих запусков этого контейнера: `docker start hrportal-postgres`. Используйте один из двух способов запуска БД. Данные находятся в томе `hrportal-data` и сохраняются после перезапуска.

Подключение в IntelliJ Database / pgAdmin: `localhost:5433`, база `hrportal`, пользователь `hrportal`, пароль `hrportal_local`. Это локальные параметры разработки. Для другой БД задайте переменные `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` перед запуском приложения. Например, `DB_URL=jdbc:postgresql://localhost:5432/hrportal`.

Flyway автоматически применяет `src/main/resources/db/migration/V*.sql`. Hibernate проверяет схему (`ddl-auto=validate`), сам таблицы не создаёт и не изменяет. Уже применённые миграции не редактируют: добавляют следующую `V3__...sql`.

Тестовые аккаунты и расписание создаются одной транзакцией только в пустой БД. Перезапуск не восстанавливает старые пароли, назначения или удалённую занятость. Отключение начальных данных: `DEMO_DATA=false` (пустая БД тогда останется без пользователей).


В IntelliJ IDEA откройте `pom.xml`, выберите JDK 17 или 21 и запустите `ru.hrportal.HrPortalApplication`.

В Windows также можно запустить `start.cmd` или выполнить:

```powershell
.\mvnw.cmd spring-boot:run
```

Порт в `src/main/resources/application.properties`: **8080**. Адрес: http://localhost:8080.

Если порт занят, запустите собранный файл на другом порту:

```powershell
.\mvnw.cmd package
java -jar target/hr-portal-0.0.1-SNAPSHOT.jar --server.port=8082
```

При первом запуске необходим интернет для загрузки Maven и зависимостей. Скрипт использует `JAVA_HOME` или JDK Microsoft из `%USERPROFILE%\.jdks`.

## Реализованные сценарии

- Общий календарь по неделям и корпусам; все имена и назначения приходят с сервера.
- Собственные предстоящие и завершённые смены из общего календаря.
- Публикация своей смены на бирже и снятие открытой публикации.
- Персональный отказ от чужого предложения: исчезает только у отказавшегося сотрудника.
- Отклик на бирже: общее предложение резервируется и скрывается у остальных кандидатов. До решения начальника владелец смены не меняется.
- При одобрении начальником назначение передаётся новому сотруднику. Обновляются календарь, личные смены и уведомления обоих участников.
- При отказе начальника назначение сохраняется у прежнего владельца. Предложение снова доступно другим кандидатам; отказанный кандидат его больше не видит.
- Адресный обмен: своя смена → смена коллеги → согласие коллеги → решение начальника → изменение обоих назначений как одна операция.
- Отмена своей необработанной заявки.
- Выбор свободных смен с отдельным подтверждением и комментарием; резервирование до решения начальника.
- Создание смен и ручное назначение сотрудника ответственным за расписание. Кнопка публикации уведомляет сотрудников. В режиме «Составить расписание» изменения хранятся в черновике вкладки до нажатия «Сохранить расписание»; затем применяются одной операцией.
- Начало и завершение сегодняшнего дежурства. Фиксируются серверные время начала, окончания, фактические минуты и отклонение от плана.
- Персональные уведомления и отметка о прочтении.
- Профиль по нажатию на имя, достижения и тестовый рейтинг от 1,0 до 5,0 с точностью до десятых. Профиль не находится отдельным пунктом бокового меню.
- Обновление общих данных каждые четыре секунды, при переходе в раздел и по кнопке «Обновить». Во время заполнения формы или подтверждения интерфейс не перерисовывается автоматически.

## Как проверить исправление биржи

1. Войдите Иваном. В «Моих сменах» выберите смену без заявки и опубликуйте на бирже.
2. Войдите Анной. Отклоните предложение Ивана. Оно исчезнет из её биржи и входящих предложений.
3. Войдите Павлом. Предложение Ивана по-прежнему доступно. Если у Павла нет пересечения по времени, нажмите «Откликнуться» и подтвердите.
4. У остальных сотрудников предложение исчезнет. У Ивана будет статус «Есть отклик · На согласовании», у Павла — личная заявка.
5. Войдите руководителем, откройте «Согласование» и одобрите заявку. Смена появится у Павла и исчезнет из личных смен Ивана.

При первом запуске уже подготовлены открытые предложения трёх сотрудников. Расписание содержит восемь недель: две прошедшие, текущую и пять следующих. Даты рассчитываются относительно первого заполнения БД; при последующих запусках расписание сохраняется.

## Архитектура

```text
src/main/java/ru/hrportal/
  config/       — начальные данные, настройки web, общий замок операций
  controller/   — HTTP, проверка входных DTO и роли пользователя
  dto/          — входные параметры и представления для интерфейса
  model/        — сотрудники, смены, предложения, запросы, время, уведомления
  repository/   — контракты доступа к данным
    jpa/        — Hibernate-реализации репозиториев
  persistence/
    entity/     — JPA-сущности и отображение в доменные модели
  service/      — авторизация, бизнес-правила, обмены, расписание, учёт времени
  exception/    — ошибки бизнес-операций
```

Подробные правила и состояния: [docs/architecture.md](docs/architecture.md).

Контроллеры возвращают JSON и используют бизнес-сервисы. Репозитории отображают неизменяемые доменные модели в JPA-сущности. Hibernate сохраняет их в отдельные реляционные таблицы; связи защищены внешними ключами. In-memory реализации оставлены только в `src/test` для изолированных тестов бизнес-правил. REST API описан в [docs/api.md](docs/api.md).

## Проверки

```powershell
.\mvnw.cmd test
.\mvnw.cmd package
```

По умолчанию интеграционные тесты используют H2 в режиме PostgreSQL и настоящие миграции Flyway; контейнер для них не нужен. Проверка на отдельной PostgreSQL: `./mvnw.cmd test "-Dspring.datasource.url=jdbc:postgresql://localhost:5433/hrportal_test" "-Dspring.datasource.username=hrportal" "-Dspring.datasource.password=hrportal_local"` (предварительно создайте отдельную тестовую БД). Не используйте рабочую БД для тестов.

Проверяются откат транзакций, идемпотентное заполнение БД, реляционное хранение коллекций, персональные отказы, межпользовательские отклики, одновременное резервирование одной смены, передача и обмен назначениями, права ролей, пересечения расписания, создание смен, уведомления и фиксация времени.

## Границы прототипа

Данные общие для всех пользователей и сохраняются в PostgreSQL. `WorkflowTransactions` объединяет HTTP-запрос/внешний вызов сервиса в транзакцию; `DatabaseWorkflow` блокирует строку `workflow_guard` до commit. Это предотвращает два одновременных назначения, включая разные JVM. Пока используется один общий замок БД, поэтому операции выполняются последовательно; для большой нагрузки понадобится более точная блокировка смен.

Поддерживается одно назначение на смену. Модель рассчитана на текущее представление календаря; для нескольких дежурных на одной смене понадобится отдельная сущность назначений.

Рейтинг и показатели профиля демонстрационные. Учёт фактического времени ведётся отдельно; для показа разрешено начинать любое своё сегодняшнее дежурство, независимо от планового часа. Автоматическая генерация, серверное хранение черновиков, исправление отметок, отчёты Excel/PDF и интеграция с тикетами пока относятся к дальнейшим этапам.

## Изменения по странице 2 Figma

- «Моя занятость»: выбор нескольких ячеек, описание, редактирование и удаление; отдельные постоянные шаблоны чётных и нечётных недель по ISO-нумерации.
- Начальник и ответственный видят занятость выбранного сотрудника. При назначении, отклике и обмене сервер проверяет личную занятость.
- «Составить расписание»: два корпуса, список доступных сотрудников, приоритет и подсветка подавших заявку. Сохранение пакета назначений атомарно. Учтённые заявки на дежурство закрываются по назначенным ячейкам.
- «Запросы»: отдельные списки заявок на дежурство и обмен, ближайшие даты в начале, отметка срочности в пределах 24 часов, причина отклонения в истории и уведомлениях.
- «Сотрудники»: создание, редактирование имени/должности/контактов/пароля и отключение аккаунта с сохранением истории. Логин после создания остаётся постоянным идентификатором. Смена пароля отзывает сессии вкладок сотрудника.
- Компактная боковая навигация; цвета и иконки взяты из Figma. Профиль и выход доступны сверху справа.

Расписание вуза пока не загружается автоматически: для интеграции нужен URL/API и формат источника. «Пара» сейчас добавляется вручную. Изменение постоянной занятости не снимает уже назначенные смены автоматически.
